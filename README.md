# Hiro Knowledge

日本語の個人用知識ノートと復習アプリ。登録 → 自力で思い出す → 答えを確認 → 自己評価 → 次回復習をひとつの画面で進める。

現在は **ローカル利用版**。2026-10-29にD1権限の再認証と一覧取得まで成功した。無料プランの実状態とAccess設定は未確認のため、クラウドDB作成と本番公開は保留している。PCとスマホのクラウド同期、実際のAccessログインはまだ確認していない。安全条件を満たす前に個人データを公開しない。

## 今すぐ使う

Windowsで **`Start-App.cmd` をダブルクリック**。ブラウザーで [Hiro Knowledge](http://127.0.0.1:8787/) が開く。

初回はローカルDBを準備し、以降のデータは `.wrangler/state/` に保存する。ブラウザーを閉じてもデータは残る。`.wrangler/state` を削除するとローカルDBを失うため、先に設定からJSONを出力しておく。

ローカル版はこのPCのloopbackだけで動き、スマホからは接続できない。Cloudflare Accessの代わりになる本人認証はローカルでは行わず、同じPCを使う人・プログラムは接続できる。共有PCではWindowsアカウントを分け、離席時はロックする。

## できること

- タイトル、内容、カテゴリー、タグ、URL、自分のメモ、理解度を登録・編集。
- タイトル/本文検索、カテゴリー/タグ/未学習/復習待ち/習得の目安で絞込み。
- 自由想起の問題と3択の問題を手動作成・編集。問題の変更前の回答履歴も保持。
- 自由想起を先に表示。答えを開いてから「忘れた・あいまい・覚えていた」で記録。
- 期限に応じた復習と次回日付の自動計算。二重送信では同じ回答を重複保存しない。
- 今日の復習/学習、登録数、復習回数、3択の正答率、カテゴリー別グラフ、学習日を表示。
- アーカイブと解除。削除ボタンを置かず、既存の学習履歴を保護。
- 全学習データのJSON出力、検証プレビューからの追記復元、CSV出力。
- PC/スマホ幅、ライト/ダーク/システムテーマに対応。

AI APIは呼ばない。外部記事の取得や全文複製も行わない。登録する内容・出典・クイズは自分で確認する。

## 学習指標の意味

「読んだ」「理解できる」「思い出せた」を分けて扱う。ニュースアプリの既読機能は存在しないため、この版ではURL・タイトル・要約を手で登録する。ニュース側から `/` に `?url=...&title=...&summary=...` を渡すと登録フォームへ引き継げる。自動保存はしない。

理解度は本人が0〜3で入力する。自由回答は自己評価で、自動採点しない。正答率は3択の客観的な回答だけを使う。未回答は0%ではなく「未測定」。カテゴリー別の正答率と弱点は3回答以上ある場合だけ表示する。興味や能力を推測しない。

復習は `src/scheduler.js` に分離。忘れたら10分、あいまいなら1日、覚えていたら直前の間隔・連続成功・過去の失敗に応じて延長し、180日を上限とする。自己評価で連続3成功かつ7日以上の間隔になった項目を「習得の目安」と呼ぶ。これは本MVPの運用上の目安で、最適な記憶モデルや長期定着の証明ではない。将来FSRSへ交換する際に回答履歴を利用できる。

日次集計は東京時間。連続学習日は活動の記録であり、休んだ日の減点はない。

## バックアップと復元

設定 → **JSONを出力**。ファイルには知識・分類・タグ・情報源・問題・回答履歴・復習状態・メモを含む。学習記録そのものなので、Gitや公開ストレージへ置かない。別ドライブなどにも定期的に保存する。

復元は設定 → バックアップファイル → **ファイルを検証** → 件数/競合を確認 → **この内容を復元する**。

- 形式は `version: 1`。全テーブルを含む完全バックアップを扱う。
- 新しいIDは追記し、同じID・同じ内容はスキップ。同じIDで内容が違う場合は競合として拒否する。
- 復元による既存データの一括消去や上書きは行わない。古いバックアップへ現在の状態を巻き戻す機能ではない。
- 不正な参照、日時、クイズ、履歴と復習状態の不整合は書込前に拒否する。書込は単一D1 batchで実行する。
- JSONは最大10 MiB・全テーブル合計50,000行。超える場合は出力時にエラーにし、復元できないファイルを成功として渡さない。大規模な保管やDB全体の復旧にはD1のSQL export/importを使う。
- CSVは閲覧用で、全履歴を含まずJSONの代わりにはならない。Excelの式として実行される値を無害化する。

Cloudflare D1のTime TravelはFreeで7日間。DB全体を上書きする復元のため、実行前に別のバックアップと対象時刻を確認する。[Cloudflareセットアップ手順](docs/cloudflare-setup.md) に方法を記載。

## 開発環境

Node.js 22以降（この環境では同梱Nodeを使用）、pnpmを使用する。

```powershell
pnpm install --frozen-lockfile
Copy-Item .dev.vars.example .dev.vars
pnpm db:local
pnpm dev
```

既存の `.dev.vars` を上書きしない。`LOCAL_DEV=true` が許可されるのはURLがlocalhost/127.0.0.1/::1の場合だけ。公開Workerでは設定しない。

```powershell
pnpm test
pnpm check
pnpm exec playwright install chromium
pnpm test:e2e
pnpm exec wrangler deploy --dry-run --outdir .wrangler/build
```

E2Eは8791/8792ポートと固有の `.wrangler/e2e-*` DBを使い、通常利用の `.wrangler/state` を変更しない。テスト用データを通常DBや本番へ投入しない。結果とスクリーンショットは無視対象の `artifacts/e2e-*/` に保存する。

## Cloudflare公開

まず [標準URLでの安全な公開](docs/cloud-deployment.md) を読む。ドメインを購入せず、Cloudflare標準URLにWorker単位のAccessを適用する。専用D1、本人メールの完全一致Allow、署名付きJWT検証を設定して進める。

本番設定はGit管理外の `wrangler.production.json`。`OWNER_EMAIL` はCloudflare Secretを使用し、メールやトークンをコード・コミットへ入れない。最初の設定ではworkers.devとpreview URLを無効化している。自分が管理できるAccess保護ホストを使う。

このアプリはHTML/JS/CSS/APIのすべてを先にWorker認証へ通す。Access JWTの署名、issuer、AUD、メールを検証し、認証設定がない場合は503、未認証は401、別Originの書込は403で拒否する。公開前チェックはAccessの設定・無料プランを実確認した記録を求めるが、記録ファイルだけで安全性を証明するものではない。

追加の月額契約・有料APIは使用しない。実際のアカウントの無料プランと他プロジェクトとの合算使用量は公開前に確認する。[公式D1料金](https://developers.cloudflare.com/d1/platform/pricing/)、[公式Workers料金](https://developers.cloudflare.com/workers/platform/pricing/) を参照。

## ファイル

`src/index.js` が認証・安全なレスポンス、`src/auth.js` がAccess、`src/api.js` がAPI、`src/validation.js` が入力検証、`src/backup.js` が復元、`src/scheduler.js` が復習計算を担当する。`migrations/` にDB定義、`public/` に画面、`tests/` に検証、`docs/` に設計と実証結果を置く。

もとの `news` は空の初期コミットだったため、既存ニュース機能・既存DB・既読情報への変更はない。Hiro Memory / Supabaseには接続・変更していない。
